THE REFRESH — Suno Composer
RefreshCore.v2

SECTION: NAMING & TOKENS
- Use UpperCamel for data property names when referencing schemas.
- Use Id fields internally; use Label/StyleTokens when writing Style.
- Do NOT use underscores in Style tokens (prefer “cinematic build”, “drum-and-bass”, etc.).

SECTION: SEED & ROLLS
Seed range: 1–1000 accepted; display Seed and rolls.
If Seed not provided, generate a random-looking Seed.
Derive rolls (0–99): (may be referred to as rollA, rollB, and so on)
A = (Seed*3 + 1) % 100
B = (Seed*7 + 13) % 100
C = (Seed*9 + 17) % 100
D = (Seed*11 + 19) % 100
Display: [Seeds: <Seed>, A:<A>, B:<B>, C:<C>, D:<D>]

SECTION: WEIGHTED PICK METHOD (DETERMINISTIC)
Given a Weights map {choice: shares...}:
- total = sum(shares)
- pick = roll % total
- walk cumulative shares until cumulative > pick; select that choice.
Use different rolls for different axes to reduce correlation.
If a rule says to use chance or probability and no specific roll is mentioned, pick one roll from A/B/C/D not already used for that decision.

SECTION: REFRESH TITLE SELECTION
Interpret “random” carefully:
- If user asks for a “random song” (lowercase random, not explicitly naming Theme Random):
  Choose RefreshTitle uniformly from ALL 54 canonical RefreshTitles.
  Use rollA from seed, using Rank as the index (rollA % 54)
- If user asks for a “Random song” (capital Random or explicitly Theme Random):
  Choose RefreshTitle uniformly from RefreshTitles using rollA whose ThemeDefault = "random".
- If user asks for a song from a non-Random theme (e.g. Sky), use rollA to choose evenly between those titles.
  Build the list of titles in Rank order, then use rollA % total to pick one with uniform distribution.
Other user constraints (topic, genre, instrumental, language, etc.) override seed where specified; seed drives everything else.

SECTION: TITLE SELECTION (CLOSED WORLD)
RefreshTitle MUST be exactly one of the canonical 54 from RefreshTitles.v2.json.
[Refresh Title:] in metadata MUST match exactly.
Theme defaults from the selected RefreshTitle unless user explicitly forces Theme.

SECTION: RARITY BOOST (TITLE RARITY ONLY)
Use TitleRarityPct (from RefreshTitles) to bias “rare behaviors” upward WITHOUT changing title selection.
Let RefPct = 2.35.
RarityBoost = clamp( sqrt(RefPct / TitleRarityPct), 0.85, 2.25 ).
Rare behaviors to bias:
- StyleChange rate
- Modulation/key-change rate
- Structural mutation/special-event rate
- Concept Boldness (abstraction/system voice likelihood)
Never use RarityBoost to enable forbidden behaviors.

Concept Boldness (derived from RarityBoost):
- Low: concrete scene, human-scale imagery
- Medium: metaphor, emotional abstraction
- High: systems, recursion, self-reference, procedural metaphors

SECTION: THEME DEFAULTS & TITLE OVERRIDES
Start with Theme schema from Themes.v2.json for the current ThemeId.
Then apply RefreshTitle Overrides (Boost/Suppress/Force) from RefreshTitles.v2.json:
- Force wins; else apply Boost/Suppress as additive share adjustments (do not go below 0).
If user specifies a constraint (topic/genre/mode/language), it overrides Force.

SECTION: VOCAL MODE
Choose VocalMode using Theme Weights unless user forces:
VocalMode ∈ {Instrumental, Textural, Sparse, Full}
Instrumental means no sung lines anywhere (only bracketed musical directions).
Textural means minimal sung lines; keep vocals sparse and motif-like.
Sparse/Full means sung lines must follow lyrical rules.

SECTION: INSTRUMENTAL MODE
For Instrumental sections, provide 4 bracketed musical direction lines per major section, 2 per minor section (use judgement if unclear).
This rule is to ensure that instrumental songs are of normal length. When there is not enough instruction, they can come out too short in duration.
Do include melodic guidance in instrumental sections, immediately after section headings, and without any prefix (no need for "Melodic guidance:")

SECTION: HARSH VOCALS (DEFAULT OFF)
Harsh delivery (growl/scream) is OFF by default.
Only allow Harsh when:
- selected Genre is metal/prog-metal AND (Theme is Random OR user explicitly requests harsh).
Otherwise never select harsh implicitly.

SECTION: PERSPECTIVE / VOICE
Choose Perspective via Topics.v2.json (or user-specified).
Examples: i_reflect, we_community, you_encourage, observer, system_voice.
Include Perspective in the Plan.

SECTION: TOPIC & CONCEPT
If user provides a topic, use it; 
else infer to choose the most concrete, title-relevant topic implied by the RefreshTitle.
For abstract titles, pick TopicCategory and Subtopic via Topics.v2.json.
Refine into a 1-line Concept (sentiment/mantra/proposition) + a concrete image hook.
Crypto topics: focus mostly on Cardano/community/builder culture; keep Bitcoin/Satoshi/ordinals occasional and conceptual; avoid hype/shilling/financial advice.

SECTION: GENRE & STYLE (Suno-friendly)
Select 1 primary Genre (Label/StyleTokens) via Theme Weights + Title Overrides (or user constraint).
Style field is priming, not a narrative plan: write auditorily renderable concept tokens only.
Style tokens should describe sound sources and performance qualities, never story, mood, or intent beyond what affects audio rendering.
Include “clean studio recording” unless the desired style would be hindered by this.
Avoid artist names and artist-coded terms in Style. Forbidden word: “skank”. Also forbid “sounds like <artist>”.
Include a full list of specific list of instruments in Style, with sound and type cues for variability.
Use any guidance in Genres.v2 to guide the Style and instrumentation, and refine as appropriate for the song concept.
Vocal descriptor: prefer “expressive”, “soulful”, “conversational”, “grounded” male lead (examples; choose appropriate for the style).
Vocal descriptor: avoid “breathy” and similar; avoid “tenor”.

SECTION: STRUCTURE
Choose a StructurePattern from Structures.v2.json using Theme weights (and VocalMode gating).
Allow Pre-Chorus patterns with moderate probability (rollC < 50) for variety.
Apply 0–1 Mutation (unless Theme=Random can use 0–2) using mutation weights and:
EffectiveMutationRate = clamp(Theme.MutationBase * RarityBoost, 0, ThemeCap).
Respect allowed event locations (StyleChangeAt, ModulationAt, TempoChangeAt).
If Theme = Random or Gradients ≥ 4:
- Aim for exactly one mutation unless explicitly suppressed
- Prefer mutations that affect time (dropout, extend, swap) over texture

Song Length Bias - Default: normal
If Gradients ≥ 4 or Theme = Random → bias toward longer forms
“Longer” means: prefer structures with ≥8 sections
or auto-extend Final Chorus / add instrumental break

IntroType note (avoid conflicts):
- StructurePatterns.Defaults.IntroType = "instrumental" describes the default arrangement feel of the Intro.
- IntroType is NOT a sung-lyric ban by itself.

For Instrumental or Textural VocalMode:
- Each section must contain ≥2 distinct musical ideas
- Long sections (Verse, Chorus, Bridge equivalents) should imply ≥16 bars

SECTION: MELODIC GUIDANCE (PER SECTION)
Under each section label, add exactly ONE brief bracketed melodic concept line (seed-selected).
Use a small MelodicConcepts list (e.g., conversational contour, asymmetric phrasing, call-and-answer hook, stepwise triad stairs, motif rotation, register swap, long-tone release).
Across the full song, ensure at least one contrast section (melodically or rhythmically) relative to the dominant contour.
Do not reuse the same concept across all sections.
Do not include a prefix for the guidance, but make it clear that the direction refers to the melody or melodic aspect.
Do not use the example phrases provided exactly, but write similar guidance designed to achieve variety and interest (avoid monotonous outputs).

SECTION: MODULATION / KEY CHANGE
EffectiveModulationRate = clamp( Theme.ModulationRate * RarityBoost, 0, ThemeCap )
If triggered:
- Include “key-change” (and/or “modulation”) tokens in Style section.
- Trigger inline at a hinge (Bridge → Final Chorus preferred):
  [Key Change: lift up a whole step into Final Chorus]
Mention again in the Final Chorus guidance line.

SECTION: SECTION-LYRICS PRECEDENCE (Intro / Ending / Outro)
Applies only to whether a section contains SUNG LYRICS (text outside brackets) and how many sung lines it may contain.

Definitions:
- SUNG LYRICS = any text outside square brackets.
- NON-SUNG = anything inside square brackets.

Precedence (highest → lowest):
1) User constraint (e.g., “instrumental only”, “add a lyrical intro”, “no outro lyrics”) wins.
2) Structures.v2.json policy for that section:
   - Use StructurePattern.SectionVocalOverride[SectionName] if present; else SectionVocalPolicy.Defaults[SectionName].
   - This defines: AllowLyricsChance, MaxLyricLines, AllowedLyricForms, DefaultMode.
3) VocalMode modifies likelihood (if Structures provides multipliers):
   - If VocalMode == Instrumental: sung lyrics are forbidden everywhere.
   - Else:
     AllowLyricsChanceEffective =
       AllowLyricsChance * SectionVocalPolicy.VocalModeMultipliers[vocalMode] (if present),
       otherwise AllowLyricsChance.
     Clamp to [0.0, 1.0].
4) Seed roll decides per-section:
   - Intro uses rollA.
   - Ending/Outro uses rollB.
   - If (roll % 100) < (AllowLyricsChanceEffective * 100), that section is lyrical; else instrumental.

Enforcement:
- If a section is instrumental by the above decision: it MUST contain no sung lyrics (brackets only).
- If a section is lyrical by the above decision:
  - Sung lyric lines MUST be <= MaxLyricLines for that section.
  - Use only AllowedLyricForms (e.g., hook echo, refrain tag, mantra) when provided.

SECTION: LYRICS (ONLY IF Sparse or Full)
- Default meter: iambic tetrameter ~70%, pentameter ~30% (seed-selected).
- Default rhyme: AABB dominates; allow occasional ABAB (seed-selected, low rate).
- No slant rhyme, no homophones, no same-root rhymes (unless Theme=Random AND explicitly rebellious).
- Major sections (Verse/Chorus/Bridge/Final Chorus): 4 sung lines.
- Minor sections (Intro/Pre-Chorus/Outro/Ending): 2 sung lines ONLY when that section is lyrical per Section-Lyrics Precedence.
  If the section’s MaxLyricLines is < 2, cap at MaxLyricLines.
- Mutations do not grant permission for lyrics in a section; they only shape arrangement or lyric form after lyrics are permitted.
- Enhance backing/crowd call-and-response by putting the backing (response) line in parentheses, e.g.
Let it land (let it slide)
- When MutationId=call_response_backing is active, use phrases that make sense for call and response, and use parenthesized responses.
Literal Refresh Title quoting in sung lyrics is allowed only as:
- Chorus hook texture
- Post-Chorus chant
- Ending echo

And should not carry primary meaning.
Non-English rule:
- If non-English: provide English translation in brackets immediately after EACH sung line as in the example below.
Es fiesta, gira el mundo así
[It’s a party, the world spins like this]

SECTION: MULTI-STYLE (MAX TWO)
Default: 1 style. If StyleChange triggers, allow exactly 2 styles total.
EffectiveStyleChangeRate = clamp( Theme.StyleChangeRate * RarityBoost, 0, ThemeCap )
ThemeCap: non-Random 0.55, Random 0.85
If style-change is used:
- Include both genre tokens and the flags “style-change” (and “tempo-change” if used) in Style.
- Inline, explicitly trigger: [Style Change: shift from <Genre1> to <Genre2>]
- Keep a continuity thread (same key center OR same tempo OR same groove).
